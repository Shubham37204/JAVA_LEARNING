in.ashokit.beans.PetrolEng

The complete flow

Let's use your Car, IEngine, PetrolEng, and DieselEng example.

Step 1 — Create an interface
public interface IEngine {
    void start();
}

The interface defines the contract.

IEngine
   ↑
   |
   ├── PetrolEng
   └── DieselEng
Step 2 — Create implementations
public class PetrolEng implements IEngine {

    public void start() {
        System.out.println("Petrol engine started");
    }
}
public class DieselEng implements IEngine {

    public void start() {
        System.out.println("Diesel engine started");
    }
}

Now we have multiple implementations of the same interface.

This gives us loose coupling.

Step 3 — Create the dependent/target class

Your Car class:

public class Car {

    private IEngine eng;

    public void setEng(IEngine eng) {
        this.eng = eng;
    }

    public void drive() {
        eng.start();
    }
}

Here:

Car
 |
 | needs
 ↓
IEngine

Therefore:

Car = dependent
IEngine = dependency type
Car = target of injection
PetrolEng / DieselEng = actual implementations
Important correction

You said:

"main class which will have one instance variable..."

It isn't necessarily the main class.

It is the dependent class (Car in our example).

It could be:

Car
PaymentService
OrderService
UserService
BillPayment

etc.

Step 4 — Create Spring XML configuration

Now we tell Spring:

"These are the objects I want you to create and manage."

<bean id="peng" class="in.ashokit.beans.PetrolEng"/>

<bean id="deng" class="in.ashokit.beans.DieselEng"/>

<bean id="car" class="in.ashokit.beans.Car">

    <property name="eng" ref="peng"/>

</bean>

Spring now knows:

peng → PetrolEng object
deng → DieselEng object
car  → Car object

These are Spring Beans.

Step 5 — Inject the dependency

This line:

<property name="eng" ref="peng"/>

is the actual Dependency Injection configuration.

Break it down:

name="eng"

Refers to the property:

private IEngine eng;

and its setter:

setEng()
ref="peng"

Refers to this bean:

<bean id="peng" class="...PetrolEng"/>

So Spring effectively performs:

car.setEng(peng);

Therefore:

PetrolEng object
       |
       | injected
       ↓
     Car.eng
Step 6 — Create the Spring Container

Now your Java program starts:

ApplicationContext context =
        new ClassPathXmlApplicationContext("spring-beans.xml");

This is very important.

ApplicationContext represents the Spring IoC Container.

It reads:

spring-beans.xml

and Spring then:

1. Reads configuration
2. Creates beans
3. Manages beans
4. Finds dependencies
5. Injects dependencies
Step 7 — Ask Spring for the object

Then:

Car car = context.getBean(Car.class);

You're saying:

"Spring, give me the Car object that you created and are managing."

Spring gives you the Car bean.

And that Car already has:

Car
 |
 | eng
 ↓
PetrolEng

because Spring already performed DI.

Step 8 — Call the business method

Finally:

car.drive();

Inside:

public void drive() {
    eng.start();
}

Since Spring injected PetrolEng:

car.drive()
     ↓
eng.start()
     ↓
PetrolEng.start()
