1. @SpringBootApplication

When Spring Boot sees:

@SpringBootApplication

you can think:

"This is the main Spring Boot configuration class. Start the application from here and do the necessary Spring setup."

Internally, it combines:

@SpringBootConfiguration
@EnableAutoConfiguration
@ComponentScan

Your understanding is correct:

@SpringBootConfiguration → marks the class as a Spring configuration class.
@EnableAutoConfiguration → tells Spring Boot to automatically configure things based on the dependencies.
@ComponentScan → tells Spring to find Spring Beans in the project.

-----------------------------------------------------------------------

Start with the actual line
ApplicationContext context =
    SpringApplication.run(SpringBootJdbcApplication.class, args);

1. SpringApplication → a class

Yes.

Think:

class SpringApplication {
    ...
}

This is a class provided by Spring Boot.

It contains a method called run().

So just like:

Math.random();

where Math is a class and random() is a static method,

we have:

SpringApplication.run();

where SpringApplication is a class and run() is a static method.

2. run() → a static method

Conceptually, its method signature is:

public static ConfigurableApplicationContext run(
        Class<?> primarySource,
        String[] args) {

    // Spring Boot does its work

    return ...;
}

3. What does run() actually return?

The actual return type of this run() method is:

ConfigurableApplicationContext

So this:

public static ConfigurableApplicationContext run(...)

means:

The run() method returns an object whose type is ConfigurableApplicationContext.

⚠️ Important correction to your notes

Don't write:

returns ConfigurableApplicationContext
↓
returns ApplicationContext

It doesn't return two different objects.

It returns one ConfigurableApplicationContext object.

That object is also an ApplicationContext because ConfigurableApplicationContext extends ApplicationContext.

4. Then why do we write ApplicationContext context?

This is pure Core Java inheritance/polymorphism.

The relationship is:

ConfigurableApplicationContext
             ↓
       extends
             ↓
    ApplicationContext

Therefore:

ApplicationContext context =
        SpringApplication.run(...);

is valid.

Why?

Because the returned object is a:

ConfigurableApplicationContext

and a ConfigurableApplicationContext is also an ApplicationContext.

So context is an ApplicationContext reference pointing to the returned ConfigurableApplicationContext object.

6. What is ApplicationContext?

ApplicationContext is a Spring interface.

For now, don't worry about its entire hierarchy.

Just understand:

ConfigurableApplicationContext
            ↓
         extends
            ↓
ApplicationContext

And conceptually:

ApplicationContext represents the Spring IOC container and provides methods to interact with the Beans managed by Spring.

That's why we can do:

context.getBean(AlienRepo.class);

Here:

context
   ↓
ApplicationContext reference
   ↓
getBean()
   ↓
asks Spring for a Bean

SpringApplication is a Spring Boot class containing the static run() method. The run() method starts the Spring Boot application, creates and configures the IOC container, and returns a ConfigurableApplicationContext object. Since ConfigurableApplicationContext extends ApplicationContext, we can store the returned object in an ApplicationContext reference called context.
